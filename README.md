# 有赞 · 品牌影棚

一个 React + Three.js 的互动服装衣架 Demo。支持选款、拿取、正反面查看与回挂，包含逐款布料响应、基础标识、原创印花、满版花纹和影棚光照。

## 本地运行

建议 Node.js 22.12 或更新版本。

```bash
npm ci
npm run dev
```

打开终端显示的本地地址，默认是 http://127.0.0.1:5173/。

```bash
npm test
npm run build
npm run preview
```

- 鼠标悬停展开，点击查看单品；触屏可左右切换。
- 左右方向键选款，Enter 查看，Esc 返回。
- 查看单品时用翻转按钮切换正反面。

## 结构

- `src/scene.js`：场景、交互状态、固定步长模拟和绘制。
- `src/surface-*.js`：布面约束、碰撞、形变场与材质绑定。
- `src/catalog.js`：款式、颜色、印花和独立运动参数。
- `src/garment-artwork.js`、`src/fabric-pattern.js`：高分辨率字体/花卉印花，以及随布面运动的条纹、迷彩、植物花纹。
- `src/studio-*.js`：影棚光照与阴影。
- `public/models/`：实际模型、模拟网格和阴影细节资源。
- `public/textures/`、`public/brand/`：扫描面料及品牌素材。
- `tests/`：几何、接缝、衣架、布料约束、材质和绘制回归。

## 当前性能优化

运动时使用随横竖屏切换的 1080p 绘制预算（横屏 1920×1080，竖屏 1080×1920）；停稳后以原生像素补画一帧，最多 3840×2160 像素，下一次交互立即恢复运动预算。面光源的阴影可见性和绒面高光采用 2×2 Gauss 采样；完整布料网格和织物纹理分辨率保持不变。

完整布料求解分配到最多 8 个 Web Workers，跨衣服碰撞保持原顺序。物理使用独立时钟，每步固定 1/60 秒，与 GPU 绘制并行，不因显示掉帧丢弃物理步。网格、约束、求解迭代、连续碰撞及 Float64 状态保持不变；逐帧对照测试覆盖全部 10 件衣服，验证位置、速度和显示形变逐字节一致。线程异常时退回完整主线程求解。

碰撞候选搜索使用 WebAssembly 三轴区间位集合，并缓存扩大后的扫掠包围盒邻居；每次检查当前包围盒仍在缓存范围内，越界立即重建。缓存只复用搜索范围，每步仍重新判断连续碰撞。保守的 Bernstein 判据排除不可能接触，实际 CCD、接触投影与所有材料约束保持原有 Float64 运算和处理顺序。每个工作线程共用最多 8 MiB 的临时内存；不支持 WebAssembly、加载失败、超出空间或候选预算时继续使用原有完整搜索。`npm run build` 会从 `scripts/contact-kernel.ts` 重新生成内核；修改该文件后也可单独运行 `npm run build:physics`。

衣架 hover 的驱动时长为 0.52 秒（实际耗时仍受设备算力影响），使用两端平滑加减速、中段匀速的转身曲线，保持金属挂钩在杆上，由同一条平滑驱动协调木质衣架转身，新旧衣服同时收展。衣架控制与布料求解各自独立，移除了随转角搬运布料粒子的处理；布料的世界坐标、角动量和相对惯性不被旋转补偿，衣摆会滞后于衣架，并在衣架到位后继续回摆。两件衣服共用展开间距，相邻切款不牵动其他衣架。

版型恢复约束使用较轻的 XPBD 相对运动阻尼，配合只耗散边伸缩的内部阻尼（保留刚体平移与旋转），耗散衣架停下后反复释放的弹性能，减轻袖子再次加速的大幅回弹；随衣架共同移动不受该阻尼影响。保留完整网格、材料约束和转身后的自由回摆。

横向排布仅调整 x 方向的布局原点，不改变粒子速度或旋转布料，也不产生衣架侧摆；相同局部形变不会因此重新滤波和上传。真实转身、重力、摩擦、碰撞和材质约束继续完整求解。收展只加快衣架驱动，布料始终按真实时间推进；快速转身时插值衣架姿态并细分完整求解，保留惯性和自由回摆。网格、材质与每步求解迭代没有缩减。单品查看仍使用真实衣架几何验证的摘离与归位路径。

显示帧在两次完整物理提交之间插值衣架姿态和已完成的布料形变场，位置与法线使用同一插值场；物理粒子、时钟和求解步不受显示插值影响。CPU 回退和 GPU 路径都保留上一完整形变，静止时清除旧插值历史。

运动期间，小尺寸背景服装使用与当前模型哈希匹配的简化绘制和阴影索引，共享完整顶点属性与形变场；选中、收展中的服装及大尺寸单品保持完整绘制，贴图、logo 和布料求解保持完整；停稳后恢复完整绘制、完整阴影和清晰度，并停止重复渲染。模型/索引哈希不匹配时自动退回完整阴影。

替换模型后可以重新生成阴影资源：

```bash
npm run build:shadows
npm test
```

自动化回归检查覆盖几何、布料、交接和绘制。专项检查覆盖转身时的衣摆滞后、衣架到位后的自由摆动，以及 4/8 个工作线程与同步求解的逐字节一致性。切款耗时、绘制帧率和布料回摆分别检查；长袖连续切换仍需实际页面与手机设备测量，不能以构建通过或静止时帧率代替验收。材质与运动参数是展示预设，并非实测面料标定。

服装仍基于两套源模型；各款有独立的长度、宽度、衣摆偏移与垂坠变化，显示面和物理网格同步调整。长袖运行时放松原始静态细褶，改用选定面料的织物纹理，避免旧照片法线和阴影把相同褶皱重复印在每件衣服上。胸口标识位于穿着者左胸。单品模式分开绘制清晰服装与淡化、模糊的背景衣架；背景静止后缓存，避免每帧重画整架衣物。

## 素材

保留应用内的模型署名和 `public/textures/*/SOURCE.txt` 中的扫描材质来源。长袖模型署名：CG Elves / Camille Kleinman。离线简化工具 meshoptimizer 的 MIT 声明位于 `scripts/vendor/LICENSE.md`。第三方模型、纹理与品牌素材沿用各自授权，本仓库未为全部素材声明统一开源许可证。

![应用预览](docs/preview.png)

短袖使用 `short-sleeve-clean.glb`：从旧资源保存的塌陷前裁片恢复完整 58,122 个顶点和 113,231 个三角面，重新计算正常表面法线。1160 个物理粒子和 2244 个模拟三角面通过有朝向的最近三角形重心坐标同步恢复；不再将过度塌陷的旧参考帧当作静态版型，印花使用当前布面坐标。需要重建时执行 `node scripts/build-clean-short.mjs`，随后执行 `npm run build:shadows`。

恢复后的短袖裁片在加载时加入浅而不对称的侧缝、下摆垂褶，显示网格、物理网格和布纹共用同一连续形变；胸口保持舒展。短袖显示位移只做两轮空间去噪，保留转动中由求解器产生的局部曲率；长袖保持原来的处理。

短袖的 `form.depth` 控制衣身前后空间，`sleeveEase` 增加袖筒空间；它们同步作用于显示模型、模拟网格、法线和布纹。品牌文字标与圆标使用从原始素材轮廓提取的 SVG，加载时以 2048px 绘制，原始 PNG 保留。需要重建矢量资源可使用 `python3 scripts/build-brand-vectors.py`（需要 Pillow 和 NumPy）。

## 扩展款式

同一版型可通过 `src/catalog.js` 更换颜色、`print` 或 `pattern`。连衣裙、外套等新轮廓需要对应的 GLB 外观模型与匹配的模拟网格，在 `src/model-config.js` 注册新类型，再校准归一化尺寸、悬挂固定点、形变网格边界、接缝碰撞及衣架间距。当前通过资源和代码配置接入新版型，尚无任意模型上传后自动适配的界面。


## 首屏加载与展开渲染（2026-10-26）

- 布料颜色与深度在同一绘制中输出，避免独立深度预绘制在衣架展开时产生白色碎斑。阴影、衣架和逐款物理参数保留。
- 启动不再对每件衣服运行 80 帧不可见预热。实际 Worker 求解保持完整。
- GLB 与模拟 JSON 使用预生成 gzip 文件，在浏览器解压；模型字节与原文件完全一致，继续通过原有阴影哈希校验。不支持解压或压缩资源缺失时回退原文件。模型与模拟数据并行请求。
- 品牌图片按实际印花需求加载。当前目录不使用吉祥物，不下载其 5.7 MB 原图；可选吉祥物使用预处理 2048px 无损 WebP，生成命令为 `python3 scripts/build-runtime-assets.py`（需要 Pillow）。
- 首轮修复使首屏模型、模拟数据、阴影索引、面料与品牌图片的文件体积合计从 29,915,893 降至 18,419,777 字节；后续模型减面进一步降至约 10.7 MB，不包含应用 JS/CSS，也不是线上网络耗时。现用面料为 cotton、fleece，旧模型和 melange 贴图不在首屏请求清单中。
- `npm run build` 自动重建压缩模型，避免源码更新后压缩副本过期。读取画布的 `data-load-*-ms` 可区分资源、服装准备、Worker 和着色器阶段；时间为从场景初始化开始的累计毫秒。
- 本地浏览器仍有数秒模型准备开销；尚未验证独立线上部署的冷缓存网络速度。此次修复不等于已经上线。


### 运行模型减面（2026-10-26）

运行入口使用 `short-sleeve-web.glb` 和 `hanging-long-sleeve-web.glb`，原始模型保留用于重建和回归。使用仓库已有 meshoptimizer 离线简化，无新增依赖。

| 模型 | 原三角面 | 运行三角面 | 原 GLB | 运行 GLB | gzip 下载 |

| 长袖（含衣架、布边） | 285,602 | 77,636 | 12,386,876 B | 2,853,684 B | 1,923,560 B |

- 顶部承重区与开口边界加锁，保留 UV、法线、AO/厚度等属性的对应关系；长袖衣架和布边不减面。既有模拟网格不变，继续驱动显示网格。
- 简化误差阈值为模型空间 0.003（按当前假定标尺约 0.85 mm）；这是简化器误差阈值，不是实物尺寸测量。
- `npm run build:models` 从原始 GLB 生成运行模型，重建匹配的阴影索引与 gzip；之后 `npm run build` 生成预览。统计与哈希见 `public/models/web-models-manifest.json`。
- `tests/web-models.test.js` 校验原承重面保留、开口边缘关联不变、全部保留顶点属性配对、刚性衣架/布边不变与运行入口引用。浏览器已检查短袖、长袖近景、翻面、切换和回挂；截图见 `docs/model-optimized-*.png`。手机实机帧率尚未测量，本轮没有推送或部署。

长袖左胸标识区域与邻接一圈保留原始内外层网格，避免两层独立减面后在形变中互相遮挡；该局部修正已构建，动态效果未运行验证。
